3// Streaming colour-managed pixel source (P6, #4040).
4//
5// The last stage of the wiring: something a `PixelIterator` can be built
6// over that runs the pipeline per pixel instead of the legacy scale.
7//
8// It is a source, not a buffer, and that is the point. C2 asks for the
9// per-pixel work to happen inside the existing iteration with no RGB16
10// framebuffer, and B3 forbids an intermediate RGB8 one. `showPixels`
11// already has a place that rewrites pixels -- the XYMap path materializes a
12// thread-local `CRGB` vector -- and putting the pipeline there would break
13// both rules at once. This reads one pixel, transforms it, and yields the
14// bytes; nothing is held between pixels.
15//
16// `PixelIterator`'s constructor is templated over its source, so this only
17// has to provide the same members `PixelController` does. It is not itself
18// templated on colour order: the order is applied to the three outputs at
19// the end, which avoids six near-identical instantiations for something
20// decided at bind time.
