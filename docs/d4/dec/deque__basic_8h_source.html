3// deque_basic: non-template chunk-map arithmetic helper shared by every
4// `fl::deque<T>` instantiation.
5//
6// FastLED's `deque<T>` is a chunked container -- a map of fixed-size chunk
7// pointers with the underlying elements stored in separately-allocated
8// chunks. Element pointers stay valid across push at either end because
9// only the chunk-pointer map ever reallocates, never the chunks. See
10// FastLED #3270 for the design.
11//
12// The map-grow policy is pure arithmetic (current capacity -> next
13// capacity) and doesn't depend on T, so it's emitted once per build via
14// `FL_NO_INLINE` regardless of how many `deque<T>` instantiations exist.
15// Mirrors the dedup pattern from `unordered_map_basic` (#3235 Tier 1C) and
16// `flat_map_basic` (#3239).

32// Compute the next chunk-map capacity when the deque's chunk map needs to
33// grow. Doubles from the current capacity (or starts at
34// `kDequeInitialMapCapacity` if `current == 0`) until the result is at
35// least `min_required_chunks`. Saturates to `min_required_chunks` if
36// further doubling would overflow `fl::size` (preventing a non-terminating
37// loop).
38//
39// Caller is responsible for actually allocating the new map and copying
40// chunk pointers across; this helper only computes the target capacity so
