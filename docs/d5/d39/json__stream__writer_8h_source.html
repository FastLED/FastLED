3// JsonStreamWriter — emit a JSON document incrementally to a byte sink
4// without ever allocating a buffer proportional to the document size.
5//
6// Motivation (FastLED#3588 follow-up): building a large JSON-RPC response
7// as an fl::json object and then serializing it to an fl::string allocates
8// TWO buffers proportional to the whole response (N-sized), which exhausts
9// the heap on classic ESP32 once WiFi is up. A streaming writer keeps only
10// a small fixed buffer live, so an arbitrarily large response (e.g. a
11// `help` listing of hundreds of methods) can be returned with a bounded,
12// tiny memory footprint. Peak memory = one small buffer + the nesting
13// depth, not the document.
14//
15// The writer performs no heap allocation itself: the scratch buffer and the
16// container-nesting stack are fixed-size members. It handles commas between
17// elements, object key/value alternation, and JSON string escaping.
