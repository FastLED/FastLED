3// The streaming pipeline core (P6, #4040).
4//
5// P6's stages have existed as separate modules for a while -- decode,
6// primaries->XYZ, chromatic adaptation, the device solve, the gamut mapper,
7// the flux scalar -- with nothing composing them. This is the composition:
8// one bind-time build, and one per-pixel call that runs the whole chain.
9//
10// The chain, and why it is in this order:
11//
12// 1. `decodeTransferU16` turns each RGB8 code into u16 linear light. One
13// semantic conversion, per B3: there is no intermediate RGB8 linear
14// buffer and no RGB8->RGB8 correction anywhere in it.
15// 2. `linearRgbToXyzQ16` takes those to s16.16 XYZ. Chromatic adaptation
16// is folded into that matrix at bind time, so it costs nothing here.
17// 3. The gamut mapper maps the target onto the device hull and solves for
18// drives -- clamping belongs to it, not to the stages before.
19// 4. `applyFluxScalar` scales linear emitter light. C4's single insertion point:
20// brightness and the power limiter compose into one scalar before they
21// get here. Inverse physical response then produces drive coordinates;
22// native encoding performs the final quantization.
23//
24// Streaming, per C2: the per-pixel call carries no state and allocates
25// nothing, so it runs inside `PixelController` iteration without an RGB16
26// framebuffer.
