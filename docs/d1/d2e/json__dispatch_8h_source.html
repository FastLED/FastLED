3// json_dispatch: type-erased core helpers for JSON-to-primitive conversion.
4//
5// Legacy `fl::detail::JsonToIntegerVisitor<T>` / `JsonToFloatVisitor<T>` /
6// `JsonToBoolVisitor` / `JsonToStringVisitor` (formerly in
7// `fl/remote/rpc/json_visitors.h`) each contained ~10 `operator()`
8// overloads (one per `json_value::variant_t` alternative). When invoked
9// via `data.visit(visitor)`, the variant emitted a `visit_fn<T, Visitor>`
10// thunk per (alternative × visitor) pair, plus the per-T body fan-out for
11// the templated visitors -- the audit in #3235 catalogued ~2-3 KB of
12// visitor codegen on LPC845.
13//
14// This dispatch layer collapses that per-(visitor × alternative)
15// explosion to **one** shared non-template body per output type. The
16// thin templated `JsonToType<T>::convert` (in `json_to_type.h`) calls
17// the appropriate core, gets back the canonical type
18// (`i64` / `bool` / `float` / `string`) plus a `TypeConversionResult`,
19// and applies per-T narrowing + range checking. The per-(T × alternative)
20// thunk explosion is gone, which is why the visitor classes themselves
21// were deleted in #3251 (no remaining callers).
22//
23// `FL_NO_INLINE` on the implementations is load-bearing under LTO --
24// without it the compiler inlines the body back at each call site,
25// defeating dedup.
26//
27// See FastLED #3247 / #3244 Tier 2E Phase 2, plus #3251 / Tier 3I dead-code
28// removal of the formerly-templated visitor classes.
29
