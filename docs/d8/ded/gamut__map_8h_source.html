3// Gamut mapping onto the device hull (P7, #4041).
4//
5// `docs/color-gamut-algorithm-selection.md` selects OKLCh chroma compression
6// and rules out the cheaper alternatives: clipping and max-normalization
7// both land about 20 dE2000 from the reference against a budget of 0.5, and
8// no amount of clamping substitutes for the objective.
9//
10// The per-pixel path here is fully bounded and contains no iterative solver
11// in the A3/B11 sense, no division, no float, and no trigonometry:
12//
13// 1. one forward OKLab transform (three cube roots),
14// 2. one comparison against a precomputed device constant for lightness,
15// 3. eight halvings, each an inverse OKLab transform and one solve.
16//
17// Chroma is compressed by scaling (a, b) toward zero rather than by going
18// polar. Since a = C cos h and b = C sin h, scaling both by one factor is
19// exactly scaling C at fixed hue -- so hue is preserved by construction and
20// atan2, hypot, cos and sin never appear.
